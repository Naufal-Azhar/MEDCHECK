Current model (2026-10-08): `Qwen/Qwen3-4B-Instruct-2507`, explicitly selected by
the user. Only this non-gated model is enabled now; earlier failure reports below
remain historical. A user-run diabetes example passed structural validation.
Follow-up live boundary tests found a personal-diagnosis refusal and grounding
failure: see [phase10-boundary-results.md](phase10-boundary-results.md).
That specific failure has since been addressed by minimum safety remediation:
see [safety-minimum.md](safety-minimum.md) for results and remaining limitations.
Passing automated checks is still not medical verification.

Implemented retrieval → bounded evidence → Featherless → strict response parsing
and source attribution. This is NOT ready for public healthcare use. Safety layer
and semantic grounding evaluation are incomplete. No API endpoint/frontend added.

Only public educational or synthetic questions; never patient data. The current

## Response contract and limitations

- System instructions distinguish evidence from untrusted user/source instructions.
- Model returns JSON: status, answer, key_points, citations, uncertainty.
- Citations must use supplied IDs and exact source excerpts. URLs and source titles
  are attached from database evidence, not generated by the model.
- Evidence budget now includes complete blocks, without final string slicing that
  could separate citation metadata from text. Existing word chunks can still end
  mid-sentence; that earlier chunking limitation is not solved here.
- Empty evidence bypasses the provider. Irrelevant non-empty evidence still requires
  model abstention; this is not independently guaranteed by current retrieval.
- Invalid JSON, citations, quotations, or truncated provider responses are withheld.
  Model refusals/insufficiency use fixed fallback text, never arbitrary model claims.
- Exact quote matching and JSON validation do NOT establish that the explanation
  follows the evidence or is medically correct. Safety prompting is not a validated
  safety layer. Human review and further safety/grounding work are required.
- No automatic repair request, retry loop, or expensive model fallback.

## Historical live test results

Two explicitly run requests for `What is diabetes?` with the same prompt/model:

| Run | Prompt tokens | Output tokens | Result |
| --- | ---: | ---: | --- |
| 1 | 1044 | 142 | Response rejected by validator |
| 2 (added diagnostic reason) | 1044 | 142 | Invalid JSON |

Neither response was displayed as a healthcare explanation. No raw provider content
was saved. Approximate combined cost at $0.04/M input and $0.08/M output:
`(2088 * 0.04 + 284 * 0.08) / 1000000 = $0.00010624`.
Actual billing depends on the account. API connectivity works, but this run does
did not establish Qwen 0.5B could satisfy the grounded response contract. At that
time Phase 10 was blocked. Current Qwen4B results supersede this historical status;
mock test success still must not be reported as model quality.

## Approved small-model debugging follow-up

User approved at most one or two size tiers above 0.5B if needed. No automatic
fallback was added. Four additional requests were made manually in this round:

| Model / prompt variant | Input | Output | Observed result |
| --- | ---: | ---: | --- |
| Qwen2.5-0.5B, valid JSON example | 1086 | 141 | Markdown prose rather than JSON |
| Qwen2.5-1.5B, same prompt | 1086 | 287 | JSON but invalid list contract |
| Qwen2.5-1.5B, shorter answer instruction | 1118 | 73 | Invalid JSON |
| Llama-3.2-3B-Instruct, shorter prompt | unavailable | unavailable | HTTP 403, access not verified |

The diagnostic 0.5B response was inspected as unvalidated developer output only,
not returned as a healthcare answer. JSON parsing and citation checks were NOT
relaxed. Prompt variants differ, so this is debugging, not a controlled quality
benchmark. All candidates remain unaccepted for grounded generation.

Official rates checked 2026-10-07 (USD per million input/output tokens):
